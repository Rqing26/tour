# 演示脚本

> 对象：课程答辩 / 验收演示者。目标是在 8–10 分钟内把六项增量功能各演一遍，并且**每一步都有数字可核对**。
> 文中的数字全部来自 2026-11-13 在干净内存库上的实测（命令见文末附录），不是估算值。

## 0. 准备（约 2 分钟）

### 0.1 启动

演示用一个**一次性数据库**，避免污染本机 `data/`，也保证每次都是同一份初始数据：

```bash
# 前端产物先入 static（若 target/travel-agency.jar 已是最新可跳过）
cd frontend && npm run build && cp -r dist/. ../src/main/resources/static/ && cd ..
./mvnw -B -ntp package

java -jar target/travel-agency.jar \
  --server.port=18080 \
  "--spring.datasource.url=jdbc:h2:mem:demo;MODE=MySQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1" \
  --spring.profiles.active=demo \
  --travel.upload.dir=.runtime/demo-uploads
```

健康检查：`curl --noproxy '*' http://127.0.0.1:18080/travel/actuator/health` → `{"status":"UP",...}`（约 5 秒后可用）。
演示入口：<http://127.0.0.1:18080/travel/>，接口文档：<http://127.0.0.1:18080/travel/swagger-ui/index.html>。

> 用 `--noproxy`：本机若开着 HTTP 代理，回环地址会被劫持成 502。

## 1. 订单审计：状态一变就留痕（P0）

**前置**：`customer` 已登录，线路「厦门海风 · 岛屿来信」余位 23。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | `customer` →「探索线路」→ 厦门卡片「预订」→ 1 人 → 提交 | 生成 `SH000010`，`PENDING`，金额 ¥1980 |
| 2 | 换 `employee` 登录 →「订单服务」→ 搜 `SH000010` →「接下订单」 | 状态 `ASSIGNED`，负责人变成「旅行顾问 · 小夏」 |
| 3 | 同一订单 →「完成服务」 | 状态 `COMPLETED` |

展开该订单的「订单变更记录」（`AUDIT TRAIL`），应有**恰好 3 条**，且每条都带操作人与当时角色：

```text
(null)  → PENDING    客户提交预订    旅行者 · 小林  CUSTOMER
PENDING → ASSIGNED   顾问接单        旅行顾问 · 小夏 EMPLOYEE
ASSIGNED→ COMPLETED  旅程完成        旅行顾问 · 小夏 EMPLOYEE
```

**数据佐证**（`GET /orders/10/events`）：`200`，3 条；`fromStatus` 首条为 `null` 表示"下单建档"这一没有前序状态的起点。

**加演（30 秒，展示"取消也留痕"）**：另起一笔——`customer` 下单杭州 1 人（`SH000011`）→ `employee` 接单 → `customer` 取消，时间线 3 条，末条是 `ASSIGNED → CANCELLED`，前两条一条不少（只追加不覆盖）。
**反向一步**：接单后由**非负责人**的员工点「完成服务」→ `403`；客户点「接下订单」→ `403`。

**可能提问**

- *为什么用一张表而不是订单上放 `updated_by`？* —— 只存最后一改会丢掉过程；审计要回答"谁在何时把什么改成了什么"，所以每次变更一行、只追加。
- *状态改了但事件没写进去怎么办？* —— 两者在同一个 `@Transactional` 里：先按旧状态条件更新订单，影响行数为 1 才追加事件，任一步失败整体回滚。`OrderEventTest.failedEventWriteRollsBackStatusChange` 用 `@MockitoSpyBean` 让 `append` 抛异常，断言订单仍是 `ASSIGNED` 且事件仍 2 条。
- *演示数据的时间线为什么是空的？* —— `DemoData` 走仓储直写，不经过业务链路，所以没有事件；这是设计结果，不是缺陷。

## 2. 分页与索引下推（P0）

**前置**：`admin` 已登录，「全部订单」。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 列表底部翻页（页大小 10） | 只请求当前页；页脚显示"共 8 条 / 1 页" |
| 2 | 状态页签点「待接」 | 列表剩 3 条，页签数字是**全局口径**（不是当前页口径） |
| 3 | 搜索框输入 `SH000003` | 停顿 300ms 后服务端按订单号命中 1 条 |

**数据佐证**（同一次会话内直接调接口对照）：

| 请求 | 结果 |
| --- | --- |
| `GET /orders?page=0&size=3` | `{items: 3 条, total: 8, page: 0, size: 3}` |
| `GET /orders?size=1000` | 回显 `size: 100`（服务端归一到 1–100，不按请求值执行） |
| `GET /orders`（不带分页参数） | 返回**数组**而非信封——旧前端与冒烟脚本靠这个形状 |
| `GET /orders?sort=password` | `400 无效排序字段：password`（白名单，不是拼接列名） |
| `customer` 调 `GET /orders?page=0&size=100` | `total: 4`，只含自己的单 |

**可能提问**

- *分页为什么改在原路径上，不会破坏旧调用方吗？* —— 只有带 `page`/`size` 才返回信封，不带仍是数组；这是 C4「接口只增不改」与验收要求同时成立的唯一写法。
- *可见性放内存过滤不行吗？* —— 全表捞回来再过滤，`total` 就得跟着算一遍全量，翻页越深越慢；现在可见性直接翻译成 SQL 条件（客户 `customer_id=?`、员工 `status='PENDING' OR employee_id=?`），`page` 与 `count` 共用同一个 `WHERE`，总数与当前页不会互相矛盾。
- *关键词里的 `%` 会搜出全表吗？* —— 会先转义成普通字符再进 `LIKE`，用例 `keywordTreatsWildcardsLiterally` 钉住了这点。

## 3. 线路封面：真实图片上传与回退（P0）

**前置**：`admin` 已登录，「线路管理」→ 桂林卡片「编辑」。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 「选择封面」选一张 PNG →「保存」 | 卡片立刻换成新图；`imagePath` 有值，`imageKey` 仍是 `guilin` |
| 2 | 把一个 `.zip` 改名成 `cover.jpg` 再上传 | `400 文件内容不是图片，仅支持 PNG、JPEG、WebP`，卡片不变 |
| 3 | 选一张 > 5MB 的图 | `413`，与"格式不对"的 400 分开提示 |

**数据佐证**（实测）：

```text
POST /routes/1/image  (PNG)        → 200  imagePath=dd87cdb0fe364b5d82fb020052e6eb08.png  imageKey=guilin
GET  /travel/uploads/<imagePath>   → 200  Content-Type: image/png  66 字节
POST /routes/1/image  (zip 改名)   → 400  {"message":"文件内容不是图片，仅支持 PNG、JPEG、WebP"}
```

**回退演示（10 秒）**：未上传过的 5 条线路读出来 `imagePath` 为空，卡片显示内置图——旧数据不回填也能读（C7）。

**可能提问**

- *为什么要看文件头而不是扩展名？* —— 扩展名由客户端说了算，改个名就能绕过；真实格式以魔数为准（PNG 8 字节 / JPEG 3 字节 / WEBP 第 9–12 字节）。内容是真图但后缀对不上（PNG 存成 `.jpg`）同样拒绝，避免后缀与真实格式各说各话。
- *上传的图为什么不放 `static/`？* —— `static/` 是构建产物，重新打包会清空；图片落在 `travel.upload.dir`（默认 `data/uploads`，不入库），由 `WebMvcConfig` 映射到 `/uploads/**`。
- *原始文件名去哪了？* —— 一律丢弃，存盘名是 UUID + 归一后缀；带 `..`、盘符、绝对路径的文件名都进不了文件系统（用例覆盖四种写法）。
- *被拒的上传会不会留下垃圾文件？* —— 大小、扩展名、魔数三步判定都在写盘之前，被拒时磁盘零残留（用例直接数目录条目）。

## 4. 经营报表：同一页面，两种口径（P0）

**前置**：`admin` 已登录。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 左侧「经营报表」 | 标题「全站经营报表」，说明「全站订单口径，含团队接单排行」 |
| 2 | 看折线 + 柱状 + 热门线路 + 员工排行 | 窗口「近 6 个月」恒 6 个点，无单月份补 0 而不是断线 |
| 3 | 切 `employee` 再看同一页 | 标题变「我的服务报表」，数字变小，员工排行区块消失 |

**数据佐证**（`GET /reports/summary?months=6`）：

| 角色 | `scope` | 订单数 | 营收 | `employeeRank` |
| --- | --- | --- | --- | --- |
| admin | `ADMIN` | 8 | ¥41060 | 小夏 4 单 / ¥14480 |
| employee | `EMPLOYEE` | 4 | ¥14480 | `[]` |
| customer | `CUSTOMER` | 4 | ¥11920 | `[]` |

月度序列（admin）：`2026-06:0, 07:1, 08:1, 09:1, 10:2, 11:3`；`months=99` 压到 24 行，`months=3` 回 3 行。

**可能提问**

- *为什么员工的报表数字比工作台小？* —— 两套口径，故意的：工作台是待办面板，员工要看见待接池（7 单）；报表是业绩，只算已归属本人（4 单）。`/dashboard` 与 `/reports/summary` 都能现场对照。
- *这些数字是内存里遍历算的吗？* —— 全部 SQL 聚合：状态与金额用 `SUM(CASE WHEN …)` 一条出一行，月度按 `YEAR()`/`MONTH()` 分组，热门线路与排行 `GROUP BY + LIMIT ?`。`DashboardService` 原来的三处全表流式统计已经删掉。
- *跨年会不会错？* —— 窗口用 `MONTHS.between` 算，`ReportTest` 里用"去年 12 月到本月"的动态窗口，任何日期跑都恰好跨一次年。
- *空库会崩吗？* —— 空表时 `SUM` 返回 NULL，SQL 里 `COALESCE(...,0)` 兜住；空窗口给空态而不是贴底的 0 折线。

## 5. 优惠码：配置、核销、快照（P1）

> 优惠码**管理端没有页面**（本期只做了后端 CRUD），配置用 Swagger UI 或 `curl`；下单页的优惠码输入框是有的。

**前置**：`admin` 在 Swagger UI 里建一张码。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | Swagger `POST /coupons`：`{"code":"autumn8","discountRate":0.80,"minAmount":0,"maxUses":20,"startsOn":"昨天","endsOn":"30 天后","active":true}` | `200`，回显 `code: "AUTUMN8"`、`usedCount: 0` |
| 2 | `customer` 下单「成都烟火 · 熊猫之约」1 人（¥1280），优惠码框填 `autumn8` | 订单详情显示"已减 ¥256"，应收 ¥1024 |
| 3 | 回到 Swagger 看该码 | `usedCount: 1` |

**数据佐证**（实测）：

```text
建码            → 200  code=AUTUMN8  discountRate=0.8  maxUses=20  usedCount=0
下单 1280×1     → 200  unitPrice=1280.0  totalAmount=1024.0  discountAmount=256.0  couponCode=AUTUMN8
核销后           → usedCount=1
填不存在的码     → 400  {"message":"优惠码不存在"}
```

**加演（30 秒）**：把该码 `maxUses` 改成 1 后再下一单 → `409 优惠码使用次数已达上限`；把码停用 → `400 优惠码已停用，无法使用`（文案直接指出是哪一条，不是笼统的"无效"）。
**快照演示**：下单成功后把 `discountRate` 从 `0.80` 改成 `0.50`，再打开那笔历史订单——减免仍是 ¥256，不按新配置重算。

**可能提问**

- *并发会不会超发？* —— 占名额只有一条条件更新 `UPDATE coupons SET used_count=used_count+1 WHERE id=? AND used_count<max_uses`，影响行数为 1 才算成功。`CouponTest` 里 10 个线程抢 `max_uses=5` 恰好 5 成功、另 5 个 409；把条件去掉，这条用例立刻红。
- *为什么存折扣率而不是减免金额？* —— 一张码要能用在不同价位的订单上，存 `0.80` 就不必为每个价位配一次。
- *金额为什么用 `BigDecimal`？* —— `12.34 × 0.85 = 10.489`，`double` 下是 `10.489000000000001`，落在四舍五入边界上不可靠；现在统一 `HALF_UP` 到分，12.34 的八五折进到 10.49 而不是 10.48。
- *配置改了历史订单怎么办？* —— 订单存快照（`coupon_code` + `discount_amount`），配置只影响新订单；用过的码也只能停用、不能删，否则历史折扣失去来源。
- *名额和订单是原子的吗？* —— 同一个 `@Transactional`：先锁线路确认余位，再核销，最后写订单。订单写失败时名额一起回滚（用例用 spy 让写入抛异常，断言 `used_count` 回到 0）。

## 6. 评价与线路均分（P1）

> 评价**提交**目前也没有页面入口（前端只做了星级展示），演示用 Swagger UI `POST /orders/{id}/review` 或附录里的 `curl`。

**前置**：第 1 节已经走完「下单 → 接单 → 完成」的 `SH000010`（`COMPLETED`，属于 `customer`，线路是厦门）。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | Swagger `POST /orders/10/review`：`{"rating":5,"comment":"行程很顺，向导耐心"}` | `200`，返回 `routeId:5`、`customerId:3` |
| 2 | 「探索线路」刷新 | 厦门卡片从"暂无评分"变成 ★5.0（1 条评价），其余 5 条仍是"暂无评分" |
| 3 | 同一订单再提交一次 | `409 这笔订单已经评价过了` |

**数据佐证**（实测）：

```text
POST /orders/10/review {rating:5}  → 200  {id:1, bookingId:10, routeId:5, rating:5}
重复提交                            → 409  {"message":"这笔订单已经评价过了"}
rating=6                            → 400  {"message":"请检查输入：rating 评分须为 1–5 星"}
GET /routes                         → 线路 5  avgRating=5.0 reviewCount=1
                                      其余线路 avgRating=null reviewCount=0
```

**反向一步**：拿一笔 `PENDING` 订单（如 `SH000002`）评价 → `403`；拿别人（`demo_guest`）的已完成订单评价 → `403`（先判归属再判状态，不透露别人订单走到哪一步）。

**可能提问**

- *怎么保证一单只评一次？* —— `reviews.booking_id` 既是外键也是唯一键，服务层不写"先查再插"，直接 INSERT 并把唯一键冲突翻成 409；并发提交只有一个落地（`concurrentDuplicateReviewsKeepOneRow`）。
- *均分会不会 N+1？* —— 列表用一条 `GROUP BY route_id` 一次取回全部均分，单条详情只查自己那一行；`ReviewTest` 用 `@MockitoSpyBean` 数调用次数，线路从 1 条涨到 6 条，`averages()` 仍是 1 次、`average(id)` 一次都没有。
- *没人评价为什么不是 0 星？* —— "0 星"和"还没人评"是两个结论，`null` 让前端显示"暂无评分"；均分保留一位小数、`HALF_UP`（4.25 → 4.3）。
- *评价会改订单状态或时间线吗？* —— 不会，`ReviewTest` 专门断言评价前后订单状态与事件条数不变。

## 7. 时间安排与兜底

| 分钟 | 内容 |
| --- | --- |
| 0–2 | 启动 + 三个账号各登录一次（顺带证明 C6：`Travel@2026` 始终可登录） |
| 2–4 | 场景 1 订单审计（含取消追加第 4 条） |
| 4–5 | 场景 2 分页 |
| 5–6 | 场景 3 图片上传（含一次被拒） |
| 6–7 | 场景 4 报表双口径 |
| 7–8 | 场景 5 优惠码（建码 → 下单 → 快照不变） |
| 8–9 | 场景 6 评价与星级 |
| 9–10 | 收尾：`/v3/api-docs`、`/actuator/health`、`./mvnw verify` 的 `Tests run: 143` |

**演示前 5 分钟自检**：`curl --noproxy '*' .../actuator/health` 为 `UP`；三个账号能登录；线路卡片显示"暂无评分"（说明是干净库）；`target/travel-agency.jar` 的 mtime 是最近一次构建。

**常见翻车点**

- 端口被上一次演示的进程占着 → 先 `taskkill //F //FI "IMAGENAME eq java.exe"`，再启动。
- 打开页面看到的是旧数据 → 用了 `data/` 文件库而不是 `jdbc:h2:mem:demo`；换个库名重启。
- 修改类请求全 403 → 会话轮换后没重新取 CSRF；页面刷新一次即可，`curl` 脚本要重取 `/auth/csrf`。
- 上传成功但图片 404 → 启动时 `--travel.upload.dir` 指到了相对别的目录；用同一个进程重传一次。

## 附录：无页面的接口怎么演（curl）

```bash
B=http://127.0.0.1:18080/travel/api
J=.runtime/demo-cookies.txt

# 登录（先取 CSRF，登录后必须重取）
T=$(curl -s --noproxy '*' -c $J $B/auth/csrf | python -c "import sys,json;print(json.load(sys.stdin)['token'])")
curl -s --noproxy '*' -b $J -c $J -H "X-CSRF-TOKEN: $T" -H 'Content-Type: application/json' \
  -d '{"username":"customer","password":"Travel@2026"}' $B/auth/login
T=$(curl -s --noproxy '*' -b $J -c $J $B/auth/csrf | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

# 提交评价
curl -s --noproxy '*' -b $J -H "X-CSRF-TOKEN: $T" -H 'Content-Type: application/json' \
  -d '{"rating":5,"comment":"行程很顺"}' $B/orders/10/review

# 线路均分
curl -s --noproxy '*' -b $J "$B/routes" | python -c "import sys,json;print([(r['id'],r['avgRating'],r['reviewCount']) for r in json.load(sys.stdin)])"
```

管理员建码把 `username` 换成 `admin`、`rating` 换成 `CouponInput` 那一段即可，字段见 `docs/API.md`。
