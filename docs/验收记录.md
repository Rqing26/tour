### 6. 本轮发现

1. **未发现产品缺陷**，六项功能的自动化与真实 HTTP 两层证据一致。
2. **文档偏差 1 处**（T8.2 已更正）：`/actuator/health` 实测返回 `{"status":"UP","groups":["liveness","readiness"]}`，`docs/API.md` 原写"只返回 `{"status":"UP"}`"。
3. **端到端脚本不共享数据库**：各脚本按"干净库"编写，在同一个库上连跑会互相污染——`rating-e2e-d20.py` 在已被 `review-e2e-d19.py` 评过价的库上 2 项失败（初始均分不为 null、同一订单二次评价 409），换干净库后 8/8。属脚本用法约束，不是产品行为异常。
4. **`DemoData` 不产生事件**：演示订单的时间线为空是设计结果（数据由仓储直写、不经业务链路），已在架构说明中写明；真实链路「下单→接单→完成」恰 3 条。
5. **容器维度未验**：本机无 docker，`docker compose` 全新环境验证与 release tag 在 D24（T8.5/T8.6）执行；CI 侧的容器 job 此前已用真实 docker 跑通过一次。

### 7. 结论

后端 143 例、前端 52 例全绿，7 组真实 HTTP 脚本（9+7+13+8+7+8+19 项）全 PASS，兼容性红线 C1–C14 逐条复核通过。在冻结新功能的前提下，本轮增量达到可演示、可回归的状态。剩余工作只有文档、演示脚本、README 与发布动作。
